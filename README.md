# 审计数工坊

面向TB、JE、财务明细账和台账的本地基础数据清洗与处理工具。表格与画布编辑同一份流程，复用Rust＋DuckDB、React Flow与AG Grid。当前执行依据为[基础数据处理完整方案](docs/07_基础数据处理完整方案.md)，实际状态与证据见[交接记录](docs/03_HANDOFF.md)和[手工验收记录](tests/手工验收_空白到导出.md)。

新版关联及多输入追加已接入执行和桌面配置，透视与范围导出已接入代码并开展回归。桌面从空白建立的两表左连接已计算、切换表格视图、保存和导出对拍。两条完整空白起建路径仍在验证，代码、自动测试、桌面验证和人工验收分别记录。旧A—E排期、渐进交互和旧70项清单已经废止。客户原件只读，客户资料与运行产物留在本地；AI后续可选，底稿自动上数不在本期范围。

## 历史验证记录

以下保留对应版本的实际证据，当前功能和验收状态以顶部入口为准。
前端与 Rust 桌面程序已构建。虚构 JE／TB 黄金样例已对拍通过：甲公司差额 38（含一条金额异常、一条未纳入记录）、乙公司差额 0；同一模板保存一次，甲乙公司配置分别保存、重开及复算通过，互不覆盖。CSV 的物理起始行与逻辑记录序号分别保留，普通记录和跨行摘要均已验证；两份不同表头的同类文件追加后，行数、原值及来源也已通过独立样例检查，其中一份表头含双引号和逗号。运行仅校验并记录画布实际引用的资料，配置中预留的其他资料不会无故阻断本次运行。缺失字段、空匹配键、重复匹配键、关联缺少输入连线、关联误用无关分支异常、重复登记异常来源、异常来源参数类型错误、关联端口与左右来源不符及重复占用同一端口九个反例均被明确阻止。每份输入文件分别为 1 万、100 万、1000 万行的虚构 CSV 规模检查均通过行数、逐组金额、总额和关联核对；加入来源记录号后的千万行档复跑用时约 425 秒，CLI 峰值工作集约 1.22 GB，运行产物约 548 MB。此前版本约 328 秒，两次运行条件未严格控制，不能直接归因。这是两份结构简单、只有两个科目代码的虚构 CSV 的单机结果，不代表任意复杂资料均有相同表现。独立运行版桌面窗口已实测画布节点显示、节点参数、虚构资料预览、模板与公司配置保存重开，以及甲公司运行后的差额、异常与未纳入结果；测试版另完成删线、恢复模板、结构校验及切换乙公司配置运行。真实鼠标拖拽和多端口连线编辑仍待验收。

配置资料时可先在公司资料面板预览原始表头与前 20 行，核实字段映射；CSV 逐条读取并限制样例行数，预览不统计总体行数。简单 XLSX 现按工作表单元格流逐行读取，预览取得限制行数后停止，全量导入逐行送入本地引擎；含大量共享字符串的工作簿在打开时仍可能占用较多内存。画布连线上点击后可用中文操作面板搜索并插入单输入节点，也可删除当前连线；插入检查点的 16 节点模板已在桌面版保存、重开并用虚构甲公司资料复算，仍为 3 组、差额 38、异常 1 条、未纳入 1 条。删除关联输入后，测试版画布从 14 条连线变为 13 条，校验阻止运行；重开共用模板后恢复 14 条并通过校验。同一测试会话中随后切换至虚构乙公司配置运行，得到 2 组、差额 0；再切回甲公司运行，得到 3 组、差额 38，导出 CSV 均与预期一致。左侧阶段导航聚焦同阶段节点和“总览”返回已在独立测试版窗口实测，收起工具库后仍可使用；节点键盘移动保存重开后的坐标已核对。

同类资料追加现在同时核对字段名称与数据类型：如果同名金额列在一侧是数值、另一侧是文本，运行会明确指出冲突字段，要求先转换，不让数据库静默改变金额口径。逐步复核只对实际数值列求和；转换前的原始文本金额可作为中间数据继续处理。虚构冲突反例与现有追加、黄金、异常样例已对拍；此次调整未重跑千万行档。

新增五文件异构表头、高基数对拍：四份 JE 先分别映射再追加，与一份 TB 汇总关联。10 万个科目组对应 JE 20 万行、TB 10 万行，完整导出的 100,001 组已逐行核对金额、差异、仅单侧项目及重复键；含跨行摘要的来源可反查到文件、物理起始行和记录号。该档本机运行约 31.1 秒，CLI 峰值工作集约 118 MB，运行目录约 26.1 MB。追加节点的左右端口现决定执行侧顺序，与工作流文件中的连线排列无关；逆序连线的类型冲突反例已对拍。此结果仍只覆盖虚构 CSV、少量字段和单机执行，不代表复杂 Excel 或百万个不同科目组的性能。发布版已重新构建；原可执行文件在产物目录保留为 `.pre-multifile.exe`。

简单 XLSX 的读取已改为逐行流式处理，不再先构建整张工作表范围。虚构内联字符串 XLSX 的 10 万、50 万数据行分别完成局部预览和全量 JE／TB 对拍；50 万行档的前 20 行预览约 0.107 秒、CLI 峰值工作集约 2.1 MB，全量运行约 30.4 秒、峰值约 185 MB，输入行数、金额和差额均相符。另用 B3 表头、空白第五行的虚构工作簿核对预览及导出，原始行号 4／5／6 与记录号 1／2／3 均保留。以上为本机单次观察；公式缓存仍待单独验证，多层表头及合并单元格已有小型虚构样例，规模边界尚未测量。

另用 50 万条互不相同的共享字符串摘要验证了常见 XLSX 存储方式：前 20 行预览约 1.8 秒、CLI 峰值工作集约 37 MB；全量运行约 36.5 秒、峰值约 195 MB，金额和行数对拍通过。相比内联字符串样例，预览的内存需求明显上升，因为 calamine 打开文件时会先加载共享字符串表；此数字只是该虚构文件的观察值，不代表任意文本长度或更多字段。XLSX 导入现与 CSV 一样单次打开并顺序处理，无须先重开文件取表头。新的独立运行版已构建，尚未重新做窗口操作验收。

金额转换采用 `DECIMAL(28,4)`。新增边界对拍发现超出四位的小数曾被静默舍入，现将这类原值及科学计数法列入异常，保留来源行；超范围整数同样不参与正常核对。合法四位小数的 `0.0001` 差额已精确对拍。更高精度、舍入方式及特殊金额文本格式需要另定明确规则，当前不会默认改值。

画布继续按真实处理步骤呈现，普通节点改为左侧输入、右侧输出；在连线中插入操作时给下游腾出横向位置，并增加“当前步骤前后”局部查看。新版独立窗口实测：在线上插入检查点后为 16 个操作、15 条连接，结构校验通过，连线与节点间距可读。通用工具库新增“文本提取”：按用户指定的源字段、规则及分组生成目标列，原行始终保留，未提取到值的行另列异常视图。该节点已有源列、目标列、规则和分组的可视参数表单，复杂规则可展开高级 JSON。虚构科目文本的 5 行样例中 3 行提取成功、2 行被标记，原始行号 2—6 保留；既有甲乙黄金样例、同类追加和画布布局检查通过。工具库直接添加步骤的位置也已调整为空白区域，避免与已有分支重叠；真实鼠标拖拽仍待人工验收。

复杂 XLSX 可在公司资料中启用“表头与合并单元格”，按实际物理列范围、表头行、明细起止行和允许补值的列号配置，并在文件输入与字段映射之间插入“表格结构整理”节点。处理时保留原始网格及行号；多层表头按真实合并区域展开并拼成字段名；明细中不论靠前还是靠后，只对选定列的真实纵向合并区域补值，同时生成 `<字段名>__filled_from_merge` 标记。普通空白不会自动填，尾部合计或说明可用明细结束行排除；若结束行截断合并区域则拒绝运行。虚构样例覆盖顶部标题、两层表头、明细下段合并、普通空白和底部合并说明，五行明细逐行对拍通过，原始空白仍可从输入节点追溯。此能力目前仅支持 XLSX 的显式结构配置，不会自行判断合计是否属于明细；含公式缓存、异常格式和超大规模复杂 XLSX 仍须单独检验。

关联节点的异常来源现在必须来自其左侧或右侧输入链，且同一异常节点只能登记一次；否则会把无关分支的异常错计进核对状态。异常来源参数类型也在结构预检时检查；CLI 新增 `validate` 命令，可不执行数据处理先验证画布。三项新增负例、甲乙黄金样例、同类追加及精度样例均已在新 CLI 上对拍。新版 release 与 debug 桌面程序均已构建。旧 release 已在同一产物目录改名保留为 `audit-data-workshop.pre-graph-check.exe`；新版 `audit-data-workshop.exe` 已独立启动，界面将异常来源参数设为非数组时明确提示“issue_sources 必须是数组”。文件选择器已实测从虚构乙 JE CSV 切换为不同的甲 JE XLSX，路径回填且甲文件的五条样例行可预览。关联与追加节点现显示左右输入端口，连接关系保存为 `target_port`；旧模板没有端口字段时仍可按原关联参数打开。新版界面在 JE 汇总至关联左侧的连线中插入检查点，结构校验通过；保存文件显示左侧来源自动更新为新检查点，右侧仍为 TB 汇总。用该模板复算甲公司仍为 3 组、差额 38、待复核 1 组。真实鼠标拖拽节点和从端口拖线仍待人工验收。

### 从检出源码恢复现有原型

在 Windows 的 Visual Studio Developer PowerShell 中，以本目录为当前目录执行以下步骤。`<Python>` 指可运行 Python 3 的实际命令；若机器上 `python` 只是 WindowsApps 占位程序，需换成真实解释器。首次安装依赖需要网络，已有依赖可使用本机缓存。当前源码已包含空白画布界面；下列命令主要验证旧 CLI 回归，桌面四操作路径另按手工验收清单检查。

```powershell
cd code/desktop
pnpm install --frozen-lockfile
pnpm build
cd src-tauri
$env:CARGO_TARGET_DIR = Join-Path (Resolve-Path '../../..').Path 'outputs/cargo-target'
$env:CXXFLAGS = '/std:c++17 /EHsc /FI' + (Resolve-Path 'cpp-compat/fmt_msvc_compat.hpp').Path
cargo build --locked --bin workshop-cli
cd ../../..
<Python> tests/generate_golden.py
<Python> tests/check_golden.py outputs/cargo-target/debug/workshop-cli.exe
node tests/check_canvas_layout.mjs
```

要构建可独立打开的桌面窗口，在完成 `pnpm build` 后，于同一 Developer PowerShell 和 `code/desktop/src-tauri` 目录使用相同的 `CARGO_TARGET_DIR`、`CXXFLAGS`，执行 `cargo build --locked --release --bin audit-data-workshop --features custom-protocol`；程序位于 `outputs/cargo-target/release/audit-data-workshop.exe`。首次本机编译 DuckDB 可能耗时较长。四操作界面请按[桌面手工验收清单](tests/手工验收_空白到导出.md)实际操作，不能只凭 CLI 回归认定界面通过。

从全新检出运行 Rust 库回归前，在仓库根目录先执行 `<Python> tests/generate_golden.py` 和 `New-Item -ItemType Directory -Path data/step1-foundation -Force | Out-Null`，然后回到 `code/desktop/src-tauri`，使用上面的编译环境执行 `cargo test --locked --release --lib`。虚构数据与生成的公司绑定保留在本地。实样测试默认忽略，需另行提供获准资料。

生成器只产生虚构测试文件与本机路径绑定；`tests/golden/workflow.json` 可直接从 Git 取得。其余对拍脚本位于 `tests/`，可对同一 CLI 运行。复杂 XLSX、实际客户资料和千万行规模须按各自验收条件单独检查。
