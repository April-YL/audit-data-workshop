# 审计数工坊：首个通用处理切片需求确认单

## 当前有效目标与需求基线（2026-10-30，用户确认）

**目标：面向审计人员处理 TB、JE、各类财务明细账和台账，完成最基本的数据清洗、计算、查找匹配、合并与汇总，并能保存规则、换资料复跑。**

表格与画布双向交互是实现目标的交互要求，不替代业务目标。用户可从任一入口建立和修改同一套步骤：表格操作更新画布；画布修改参数、连线或分支后，表格显示所选步骤的有效计算结果。画布不是仅供查看的操作日志。

本节为当前需求依据；下方首个通用处理切片保留为历史黄金样例。旧文档中固定画布主入口、表格主入口、渐进交互改造或旧批次顺序与本节冲突时，以本节及[最新开发路线](04_开发路线.md#当前有效开发顺序2026-10-30)为准。产品目标旧文档、README和专项设计本次未改，不作为冲突条款的继续实施依据。

### 输入、输出与边界

- 输入：本地 CSV／TXT／TSV／XLSX 中的财务资料；每份输入分别确认工作表、表头、明细起止位置及字段类型，不按文件名推断业务规则。
- 输出：处理结果、异常和未纳入记录、来源及处理步骤；支持明确选择部分行列导出，保存流程后可重新计算。现有CSV导出与拟新增选择性导出应区分。
- 技术基础沿用 Tauri＋React／React Flow＋Rust＋嵌入式 DuckDB；表格和画布共用处理规则与计算引擎，不在前端另做一套金额计算。
- 不做：底稿自动上数。AI为后续可选辅助，关闭AI仍须完成基础处理；OCR、完整Excel函数兼容、完整Power BI／DAX能力、云端协作不纳入当前基础范围。
- 原始资料只读；客户资料及outputs不入Git。当前仅确认文档范围，代码、测试、依赖、构建和Git须分别按范围授权。

### 核心需求与验收口径

| 通用能力 | 必须提供的行为 | 虚构验收样例／正确结果 |
| --- | --- | --- |
| 筛选及反选 | 列头值选择、条件筛选、排除所选值；区分反选勾选项与对整组条件取反，明确NULL归属 | 公司A金额10、20，公司B金额30，公司NULL金额40；选A得到2行30，排除A且明确包含NULL得到2行70 |
| 求和及多条件筛选 | 按当前筛选后的全量结果合计；支持全部满足／任一满足，显示金额异常和空值数量 | 上例按“公司A且金额大于10”得到1行20；按“公司A或金额大于20”得到4行100；预览只显示1行也不改变全量合计 |
| 行列处理及部分导出 | 保留／删除／移动／更名列；按条件或明确来源记录保留／排除行；导出范围可审阅 | 4行中仅保留公司A两行，导出公司和金额两列：文件2行2业务列、金额30；原表不变；删行规则保存重跑可复现，不以预览位置作为记录身份 |
| 添加原始行ID | 将原文件行号作为可用字段；文件、工作表、记录身份共同追溯；与当前结果重新编号分开 | 两文件都有第7行时来源身份不同；排序后原始行号不变；汇总结果通过组成明细追溯，不伪造单行ID |
| Excel风格公式新增列 | 提供文本、数学、逻辑、日期等函数分类、参数提示和试算；明确支持清单，新增列可指定位置 | 公司A、已格式化日期2026-10-30、原始行号7组合为A-2026-10-30-7；100.25减30.10为70.1500；LEFT对100201取4位为1002；缺值、除零保留错误原因 |
| 查找匹配／Join | 支持单键／多键、选择带回列及连接方式；保留匹配、仅左、仅右状态，明确重复键政策 | 左表资产X=100、Y=50；右表X=120、Z=30；全匹配结果X／Y／Z三键，X差额-20，Y／Z为单侧；右表多一条X必须提示重复，不能静默选首条 |
| 多表合并 | 各表先整理表头、尾部及类型，再按映射纵向追加，保留来源 | 一表顶部2行说明、2条明细、末行合计；另一表异名表头、1条明细、尾部说明；显式整理后追加3行，原值及来源逐行一致，合计不重复纳入 |
| 透视汇总 | 配置行维度、列维度、数值与筛选，求和／计数，查看汇总组成明细 | A公司1月10与20、2月30，B公司1月40：月份展开后A为30／30、B为40／空；空组不伪装成真实0，总计100，可回查四条明细 |

金额样例使用当前定点精度口径；不同币种未明确换算或分组时不得混合求和。日期解析、TEXT类格式化和原始行号转文本属于拟补能力，样例不是现有函数兼容声明。正式实现前每批补足空值、重复键、金额格式、编码前导零、日期歧义和数据量边界的固定预期。

### 双向交互的共同验收要求

1. 在表格设筛选生成真实可执行节点；在画布把同一节点条件由A改为B，计算后表格更新为B，往返不重复创建节点。
2. 画布建立多表匹配后，表格可复核匹配结果并通过匹配配置入口修改同一节点的键和带回字段；不能把改单元格当修改连接规则。
3. 选择任一步骤可查看其输入／输出。修改历史步骤与从历史步骤新增处理的含义分开，新增时明确插入位置或分支，受影响下游结果失效。
4. 参数修改同步不等于全量结果已经更新；待计算、运行中、有效、失败状态明确，旧结果不得冒充新规则结果。字段、数据、合计与导出必须属于同一步、同一版本和同一结果类别。
5. 表格预览仅为局部展示，处理／合计／导出按声明的全量范围执行；全量筛选选项不得仅从预览行生成。保存重开、撤销重做后两种入口仍一致。
6. 任意单元格自由改值不由“双向交互”自动包含；如需加入，先定义记录定位、改值日志与换料复跑含义。

### 举例与通用能力

公司＋日期＋行号组合是任意字段组合公式的例子，不固定字段个数、字段种类或新列位置，也不自动保证唯一性。二级科目编码提取是按实际编码长度或分隔规则使用文本函数的例子，不假定各公司的层级编码相同。固定资产两期比较、TB与JE核对是匹配、汇总与差额计算的组合验收场景，不开发专用业务按钮；TB与JE须先对齐主体、期间、科目及金额方向。

### 需求闸门与验证分级

目标和方向已确认；本轮仅将五份文档落盘，不构成代码开工许可。开发顺序见路线；每批开工前列具体代码文件、规则、样例、产物目录及停止条件再确认。上表是目标黄金预期，尚未为新增能力执行测试。验收依次区分：代码存在 → 自动测试通过 → 桌面路径验证 → 用户人工验收；一项不能替代另一项。历史样例和证据保留下方，不能据此宣称新目标已完成。

## 3. 验收标准与对拍方法

1. **字段及来源**：不同表头映射到相同规范字段，公司取已确认配置。明细可定位源文件、工作表、原始行；汇总和关联结果可反查参与源行，甲 6602 还须提示关联的异常源行。
2. **旧版黄金样例的类型及异常**：JE 输入 7 行；金额转换有效 6 行、无效 1 行。无效行不参与数值汇总，异常结果保留原值；不得静默丢行、把“错误”变成 0，或混同空值与 0。
3. **筛选及守恒**：有效 JE 净额共 165；命中 5 行、净额 160；未命中 J-A:6 净额 5。核对式：165＝160＋5。TB 共 4 行，净额 122。
4. **关联及差额**：两侧均有的 3 组，各侧净额合计均为 110；JE 单侧 50，TB 单侧 12。核对式：160－122＝50－12＝38。逐组结果必须与上表一致；甲 6602 不能标成“已完整核对”。
5. **精度**：使用十进制定点数；本整数样例逐组及合计必须完全一致，容差为 0.00。含小数的业务容差须另行确认。
6. **键重复**：本例先按“公司＋科目”汇总 JE，再关联。若 TB 出现同键重复，应按显式汇总规则处理，或报告非唯一键并阻止默认一对一关联；不得静默产生多对多放大。
7. **保存及复用**：保存并重开工作流后，节点、连线、参数、字段映射与公司配置可复现上述结果。逐家公司运行的结果与异常相互隔离；跨公司合并须由明确节点执行。

对拍顺序：人工逐行检查原始行与净额，再核对异常、未命中分支、分组结果及金额守恒，最后重开工作流复算。程序运行成功不代替 J-A:5 的业务复核。
