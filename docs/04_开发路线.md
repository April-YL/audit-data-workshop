## 已实现预览规则与验证证据

### 10.1 统一节点预览归属规则（2026-10-29 补充，列明路径已实现）

实现与验证范围见第0节、HANDOFF及手工验收清单；本节是后续节点必须复用的设计约束，不代表慢请求、多输入和规模场景全部通过。

此次缺陷属于界面状态管理和数据来源归属错误，暴露的是处理链共用预览职责未完整设计。修复按以下行为约束实施，不只对字段映射节点增加特殊显示条件。

| 视图 | 数据来源与显示要求 |
| --- | --- |
| 原始表格 | 原文件、工作表及物理行列；作为输入节点显式查看或明确标注的来源追溯，不作为下游结果的默认替代 |
| 本步输入 | 当前节点实际输入端口所连接上游的有效输出；输入整理已应用时须采用整理后的结构和明细，未运行只能称为局部输入样例 |
| 本步输出 | 当前节点当前规则所生成的有效输出；未生成、失败或过期时明确提示，不用输入样例冒充输出 |
| 正常／异常／未纳入等结果 | 按节点支持的输出类别分别展示，保留类别和来源；不因切换类别沿用上一份数据 |

共同约束：

1. 每份预览明确归属项目、节点、输入／输出方向、端口或结果类别、输入身份及规则版本；全量运行结果关联对应运行批次，异步请求带可判定先后与有效性的标记。此处规定信息职责，具体数据结构和接口在修复批设计，不要求现在引入持久化缓存框架。
2. 标题、列名、记录、物理来源和统计状态取自同一有效预览。底部默认跟随选中节点；配置面板、选中状态和预览不能分别指向不同节点。归属或有效性无法确认时显示待生成／已失效／失败，并清空旧表。
3. 显示切换不改变计算规则；输入、参数或连线改变须使受影响结果失效，初期可整次失效。撤销／重做恢复配置后，只有身份与版本核实一致的结果才可展示，否则重新取得；历史批次仍独立保留，不冒充当前结果。
4. 慢请求返回时重新核对当前项目、节点、版本和请求标记。用户已切换节点、换项目、删节点或改规则时，旧响应不得覆盖当前视图；加载和失败状态也不得继续展示无关旧表。
5. 局部输出计算复用 Rust／DuckDB 的同一节点规则；不在前端再实现一套近似转换。暂未支持预览的节点必须显式提示，支持多输入的节点按实际端口区分输入，不猜定默认来源。
6. 新增或修改节点，除单项计算外，必须验收与上游、下游的组合，以及切换、变更失效、撤销／重做和迟到响应；报告明确哪些只通过引擎、哪些通过桌面。详细场景和状态见[专项验收清单](../tests/手工验收_空白到导出.md#preview-ownership-acceptance)。

退出标准：专项必测场景有逐项证据，当前缺陷复现路径已通过修复验收，并核对预览与实际运行结果的字段、原值及来源一致；未实现的预览能力明确提示。补充文档、编译成功或旧回归通过均不能单独将此项标为完成。

## B批已实现规则与历史证据

本锚点仅保留外部引用兼容，不再指向待开发方案。以下为历史实现事实；CLI后续已修复，以HANDOFF修复记录为准。

### 统一B批已实现规则、证据与待验（2026-10-30）

- 实际模块：result_queries.rs负责全量统计及组成明细，formula.rs负责公式解析／检查／SQL编译，table_ops.rs负责排序、重复、去重、多条件及新版汇总；四个独立前端组件接入表格入口与右侧规则编辑。新增derive／sort／duplicates／deduplicate，aggregate版本2；旧节点与配置保留兼容。统一清单28文件，未改依赖或CLI接口。
- 金额规则：DECIMAL(28,4)，通过缩放整数计算四则运算，除零／溢出／超四位结果标错；数字原字段超精度不因CAST舍入变有效。IF仅采用所选分支错误；公式逐行失败保留原行，新值为空并记录原因。统计空合计不冒充零；查询与预览共用身份，已完成批次的查询串行避免独立连接争用。
- B4固定规则：排序字段可多选、各自升降序、NULL最后，同值保留前序；用__order传递给后续处理、预览及CSV。重复按所选字段精确分组，NULL同组、空字符串不同，不自动改大小写或清空格；重复标记／条数／组内序号列显式命名并防冲突。去重按明确顺序保留首／末，移除行进入未纳入。多条件all／any，最终IS TRUE纳入，其余进入未纳入。无可靠顺序的旧多输入结果拒绝猜首末，不扩展D批。
- B3固定规则：新汇总旁支不改接明细下游，多键、多求和／记录数／非空计数／去重计数；去重计数不计NULL，空字符串计一种。NULL分组独立，求和附空值数，全空组金额为空。组成明细按批次保存规则回查，上限200行并返回全量成员数，隐藏空键标记区分NULL及空字符串；汇总后映射不伪造单行来源。
- 证据：前端25项，Rust release库20项含既有获准实样全部通过，无跳过；TypeScript／Vite和三个新Rust模块格式检查通过。201行虚构组合验证全量1200、筛选1行／未纳入200行、汇总后计算250、来源及保存重开；六行边界覆盖去重首末、排序、重复、空组与条件。甲乙旧黄金通过同引擎库核对，金额与异常保持。20行实样工作副本18行金额有效／2行金额异常，Python Decimal独立逐行核对金额、文本及自核差额差异0，原件未变。完整实样B批桌面组合不在已通过范围。
