# 审计数工坊：技术架构与节点契约

> 2026-10-26 改造方案基线。Rust＋DuckDB 本地执行、部分节点与虚构数据对拍已有实现；新的空白画布交互和保存对象仍待开发。业务目标见[产品目标](00_产品目标与边界.md)，窗口与能力见[画布设计](05_第一版画布与通用能力设计.md)，实施批次见[开发路线](04_开发路线.md)，既有样例见[需求确认单](01需求确认单.md)。

## 1. 从资料到结果：同一条处理链

新建空白画布 → 在文件输入节点选择并局部预览资料 → 用可视节点配置结构、字段和处理规则 → 校验画布结构及本次输入绑定 → 预览选定节点的局部结果 → 本地全量执行 → 查看每步控制数、异常和来源 → 导出正常及异常结果 → 保存处理项目或另存模板。预览不能替代全量核对，运行成功也不能代替业务异常复核。单文件、异构多文件、同类文件组和多公司批量都使用这条链；公司配置不是普通处理的必要入口。

真正可执行对象是一张有向无环节点图，允许分支、汇合、多输入和多输出。原七段划分可作为旧设计记录，不再作为界面导航；顶部工具按操作用途查找，分类不决定执行顺序。

## 2. 五个相互衔接的技术部分

| 部分 | 责任 | 第一版路线与边界 |
| --- | --- | --- |
| 交互画布 | 让用户从空白建立真实处理流、配置节点并查看结果 | Windows 本地桌面优先；沿用 Tauri 2＋React Flow。顶部工具、中央画布、所选节点配置及按需展开的结果区使用同一份节点图。前端只接收字段、局部预览、统计和状态，不接收全量数据。 |
| 工作流控制 | 保存、验证、编排同一份规则 | Rust 定义版本化节点与输入／输出端口、校验连接和字段、生成执行计划、管理取消／进度／运行记录。画布结构校验与本次文件绑定校验分开；React Flow 的节点位置只是显示信息，不能单独充当可执行工作流。 |
| 文件接入 | 理清 PBC 的物理格式，保留来源 | Rust 已接入 CSV、简单 XLSX 和显式配置的复杂 XLSX 小样例。CSV 记录物理起始行和逻辑记录序号；Excel 记录工作表、绝对行与列。复杂合并与多层表头须继续用真实资料及大文件检验。接入后的规范化表交给同一引擎。 |
| 表格计算 | 对大量行执行通用节点 | 嵌入式 DuckDB 负责筛选、计算、追加、汇总、关联、排序和导出；Rust 负责节点语义、参数校验与 SQL 生成。小表与大表的业务规则相同，按资源调整批次、物化及磁盘溢写，不按行数切换到第二套业务逻辑。第一版不引入 pandas 或第二个 Polars 执行引擎。 |
| 证据与保存 | 支撑简单处理、复用、复跑与追溯 | 底层区分处理流程、本次输入绑定、可复用模板和运行记录；普通项目可一并保存前两者。运行记录保留输入指纹、节点版本、控制数、异常、结果及必要的本地中间数据。源资料不写入画布定义。 |

文件接入不是第二套计算引擎：它只负责将复杂物理资料转成带来源定位的表。AI 是可选建议入口，不属于上述五部分运行所必需的组件。

## 3. 四个保存对象与旧文件兼容

| 对象 | 保存内容 | 用户如何使用 |
| --- | --- | --- |
| 处理流程 | 稳定节点 ID、节点类型与版本、输入／输出端口、连线、参数和画布位置；显示信息与执行规则分开 | 说明“怎样处理”，不预设 JE、TB 或公司。画布结构可独立于当前文件绑定校验。 |
| 本次输入绑定 | 每个文件输入节点对应的本地路径、工作表、数据区域，以及与该资料相关的结构设置 | 用户直接在输入节点配置。普通项目可与处理流程一并保存；文件移动或内容变化时提示重新确认。 |
| 可复用模板 | 从已完成流程另存的规则及所需输入位置；可选存不同格式的字段映射配置 | 下次打开换文件并核实字段，不强制先建立公司配置；批量运行提供多组输入绑定并分别留下结果。 |
| 运行记录 | 本次流程和绑定的版本／快照、文件指纹、节点版本、各步控制数、异常、来源、输出和复核状态 | 与可编辑流程分开。修改流程不得改写既有运行证据。 |

原始数据不复制进流程文件。版本化 JSON 和运行本地数据的具体 Schema、原子保存、脱敏及迁移规则在 A 批次定稿并用回读样例验证。现有 `workflow.json` 与 `company.json` 保留兼容读取，不直接覆盖或静默改变既有样例；旧“公司配置”可以转换成多输入绑定或批量配置，但不再是单文件操作前置条件。实际源列名和输出字段通过可视字段映射节点及可选绑定配置表达；映射节点可出现在真实输入结构允许的任意后续步骤。科目代码等标识字段按文本处理，保留前导零。跨公司合并必须是显式节点操作。

## 4. 所有节点共同遵守的契约

每种节点都必须登记下列内容；工具库、手工配置和未来 AI 建议使用同一份登记表，不为某个科目或场景另写执行入口。

| 契约项 | 必须说明 |
| --- | --- |
| 身份与输入 | 类型 ID、语义版本、命名输入／输出端口、上游表结构要求；列的类型与空值政策；金额精度与科目编码口径。每条连线明确从哪个输出口到哪个输入口。 |
| 参数 | 必填项、默认值、可覆写范围、排序及匹配规则；常用项有可视表单和上游实际字段选择，运行前校验，不能靠引擎猜测业务口径。 |
| 输出端口 | 主结果及需要的异常、未纳入、左未匹配、右未匹配等端口；每类行都有确定去向。未连接的异常仍在运行复核面板可见。 |
| 控制数 | 输入／输出行数、指定金额合计、异常数、键重复数及字段变化；汇总节点另给组数，关联节点另给各匹配类别数量。控制数须来自全量运行，预览数另标；变更配置后旧预览和旧控制数标为过期。 |
| 来源与状态 | 行保留操作沿用源行定位；汇总通过保存的分组键及输入快照反查成员；关联同时反查左右输入。规则失败和资料异常分开，数值相符与异常已解决分开。 |

参数或连线错误须在画布上定位具体节点并阻止运行；画布结构错误和本次资料未绑定分开说明。可定位到原始行的资料错误进入异常端口并保留原值，清洗前可查看受影响行及前后差异。筛选可以先加布尔标记，再由明确分支选择是否纳入；标记为否的记录不能无痕消失。重复、空值或异常不自动删除或填补。去重、跨行、排序和一对多关联必须保存决定结果的键与顺序。关联前检查键基数；默认一对一时重复键应报错或进入异常，不静默产生多对多金额放大。

首个切片实现的通用节点组合为：CSV／简单 Excel 输入、字段映射、金额类型转换、计算列、标记与筛选、同类追加、按键汇总、按键关联、逐步检查、正常及异常导出。文本解析、合并单元格、多层表头、宽长转换、跨行计算等仍属于[画布与通用能力设计](05_第一版画布与通用能力设计.md)的第一版**定义范围**，之后按独立样例分批实现；不能由首个切片的通过推定这些能力已具备。

## 5. 精度、异常和来源：首个样例如何检验

金额从原始值显式转成十进制定点数；无效值、空值、零分别表示，不用二进制浮点误差解释账务差异。规范化输入行携带文件指纹、资料角色、公司、工作表或 CSV 记录序号、原始行位置。CSV 中字段可包含换行，因此同时保存“逻辑记录序号”和“物理起始行”；简单样例的二者对应关系见[需求确认单](01需求确认单.md)。

逐行操作传递来源引用。对汇总或关联，不在每个结果单元格拼接成千上万个来源行号；运行时保留必要的规范化输入／检查点和分组、关联关系，点击结果再按键反查参与行。保留这些本地证据会占用磁盘，运行前应提示空间需求，保留期限和清理策略待实施验证。

样例中的甲公司 6602：可转换 JE 净额与 TB 都是 80，但还有一行同组 JE 金额为“错误”。异常按“公司＋科目”关联到汇总组，显示“数值相符、资料异常待复核”，不得显示“已完整核对”。若异常行的分组键也无法辨认，应列为未归组异常，阻止相关总体被误判为完整。每步复核同时展示正常结果、异常数量、未匹配项和控制数。

## 6. 本地执行、预览与数据规模

Rust 分别校验工作流结构和本次输入绑定，再按依赖顺序生成 DuckDB 查询；值用绑定参数，字段和表标识符按已知结构校验／引用，不接受任意生成 SQL 直接执行。可连续执行的简单操作可合并，分支、汇总、关联及复核点按需要物化。输入节点须提供局部原始预览，结果接口须按选定节点提供字段、分页样本、受影响行及前后对照；全量运行另外计算控制数，不能用前若干行预览代表总体。配置或上游变化须使相应预览及运行结果失效。大表按批接入，设置内存与临时目录预算；使用 DuckDB 的磁盘溢写能力，但连接、排序、汇总叠加时仍可能内存不足，不承诺“无上限”。运行记录应给出明确失败节点和资源原因。基础处理默认不需要联网，外部扩展的安装或启用须显式纳入部署和权限设计。

规模验收设计为约 1 万、100 万、1000 万行三档虚构数据，涵盖单文件、异构多文件、多公司、无效金额与重复键。各档复用同一节点语义；逐项核对行数、金额守恒、匹配类别、异常、导出和来源反查，并记录总／节点耗时、峰值内存、临时磁盘、结果文件大小及硬件信息。性能阈值须先取得目标机器内存与磁盘基线后确定。Excel 单工作表容量有限，千万行档用多文件 CSV 等输入，不以单张 Excel 工作表作测试条件。大结果优先考虑 CSV／Parquet 分卷或分区输出；Excel 只在其容量和人工复核适用范围内导出。

## 7. 可选 AI 与会计／审计知识

不启用 AI 时，用户仍能手工完成全部节点配置、执行和复核。启用后，AI 仅帮助提出候选字段映射、节点顺序、规则参数或解释，不能直接提交任意生成 SQL／代码给执行引擎，也不能自动把“建议”标为已核对。

| 知识部分 | 解决的问题 | 首步组织方式 |
| --- | --- | --- |
| 权威资料 | 准则、制度和审计要求从何而来，适用地区／日期／版本是什么 | 保留来源、版本、有效范围及许可信息；原文由人核对，不把未经验证的 PDF 当成直接执行规则。 |
| 业务本体 | TB、JE、报表、各类台账及公司、科目、凭证等对象如何关联 | 小型结构化字段与关系字典，列出同义词、必要键、业务限制；行业差异用扩展项表达。 |
| 场景方法／Skill | 某类审计任务通常需要哪些资料、检查和人工判断 | 可追溯的步骤模板及适用前提，区分通用方法与项目／事务所内部规范。 |
| 可执行规则 | 真正交给节点运行的筛选、转换、匹配和控制口径 | 版本化结构参数，附来源和人工确认状态；只能通过统一节点校验后运行。 |

AI 数据边界：默认不发原始 PBC；用户明确调用时，由本地程序按字段结构、统计信息、异常类别及经选择／脱敏的少量样本组成候选上下文，并显示将发送的内容。样本按资料类型、异常和代表性设计，不能机械地取“前 50 行”；具体抽样、脱敏、模型部署及外发审批规则后续单独确认。全量数据处理留在本地 DuckDB。模型输出先成为待审查的工作流草稿，经节点契约、字段存在性、权限和局部预览检查，再由用户决定是否纳入正式模板。

## 8. 实施前提与尚未验证的边界

- 当前项目已有程序代码、虚构黄金与负例测试、CSV 分档规模测试及复杂 XLSX 小样例，具体通过范围与边界见[README](../README.md)和[HANDOFF](03_HANDOFF.md)。它们不证明本轮空白画布交互、全部节点表单、真实鼠标操作或复杂 XLSX 大规模性能。
- Rust、MSVC 和 Windows SDK 已安装并完成现有程序构建；新窗口、保存格式、旧版读取及逐节点结果接口仍须按 A—D 批次开发和验收。代码或测试写入须另行取得范围确认。
- 运行证据保留期限、磁盘配额、最终 UI 尺寸、AI 服务提供方式及复杂资料性能门槛仍待验证，不作为已验收承诺。
- 增加新节点须登记类型和语义版本；旧工作流应继续可读，无法兼容时给出显式迁移与差异报告，不静默改写历史运行结果。
